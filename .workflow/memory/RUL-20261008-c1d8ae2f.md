只要候选池里存在代理候选，lib/transport.js 的 dialList() 就把 direct 条目从可拨列表剔除——绝不直连。拨号失败时不许换候选，必须等 400ms/900ms（PROXY_DIAL_ATTEMPTS=3）重拨同一个代理；等待受 AbortSignal 约束，总预算 waitBudgetMs（main.js 传 UPSTREAM_WAIT_BUDGET_MS=35s，低于 60s 的响应头超时）。所有候选都失败才抛 ENOROUTE，文本含「direct dialing stays disabled while a proxy candidate exists … set the plugin setting proxyUrl to "off" to dial directly」。

只有两种情况允许直连：(a) 一条代理候选都没有（实时探测不到，也没有 heldProxies 里记住的）；(b) 设置填 off/direct（DIRECT_SENTINELS -> resolveProxyCandidates 返回 forcedDirect=true，同时清空 heldProxies）。

为什么是铁律：直连=大陆出口，muse-spark-* 这类 region 受限模型必被 403 RegionError。v0.5.2 及以前是「一次拨号失败就换下一个候选」，直连会在同一条请求里赢，于是会话被静默钉在大陆出口——已实测复现并修掉（v0.5.3），不要再恢复那种兜底。改路由前先读 lib/transport.js 的 dialList/walk 与 main.js 的 createTransport。
